# 4. PANASONIC TARGET DEFINITION

The proposed CNN-LSTM target is:

```text id="0m3j7m"
Battery_Temp_degC
        ↓
Surface Temperature
```

Verify precisely what this temperature represents.

Determine:

* Surface temperature or another measured temperature
* Sensor location
* Sensor response characteristics
* Whether it represents the cell surface
* Whether it can be treated as the ground-truth target
* Whether multiple temperature channels exist
* Whether temperature is synchronized with voltage/current
* Whether the target has missing segments

Document any ambiguity.

This distinction is important because the TrustSense project ultimately concerns **virtual temperature sensing and thermal-field inference**, not generic temperature prediction.

# 6. CHECK DATA-LEAKAGE RISKS

This is mandatory.

Determine whether the proposed train/validation/test split can create leakage through:

* Random row splitting
* Same drive cycle appearing in multiple splits
* Same battery/cell appearing in multiple correlated partitions
* Overlapping sequence windows
* Normalization fitted using test data
* Feature engineering using future information
* Duplicate measurements
* Repeated operating profiles
* Interpolation across train/test boundaries

The final pipeline must prevent leakage.

The handbook specifically requires time-series splitting by appropriate units such as cell, cycle, vehicle, operating profile or experiment.

Therefore determine the correct splitting unit for this dataset.

# FINAL RULE

This is still a **data-understanding and validation phase**.

Do not:

* Train the CNN-LSTM.
* Train any ML model.
* Tune hyperparameters.
* Build the API.
* Build the frontend.
* Create database tables.
* Modify raw datasets.
* Merge datasets prematurely.
* Claim cross-dataset generalization.
* Claim that Panasonic performance transfers to Oxford or NASA.

The correct progression is:

```text
Research Papers
        +
Project Handbook
        +
V1 Thermal Requirements
        +
Dataset Folder
        +
Official Dataset Sources
        ↓
Verified Dataset Understanding
        ↓
Data Quality Validation
        ↓
Leakage-Safe Split Design
        ↓
Cross-Dataset Compatibility
        ↓
IEEE Benchmark Reproduction Plan
        ↓
Model Implementation
```

The immediate objective is **not to build the model**.

The immediate objective is to ensure that we know exactly:

```text
What data we have
What each signal means
What the target actually represents
How the data should be split
What Panasonic can prove
What Oxford can prove
What NASA can prove
What the IEEE benchmark requires
What data problems must be solved first
```

Only after this dataset analysis is complete and the data is considered sufficiently ready should we move to the next phase: **baseline implementation and faithful IEEE CNN-LSTM reproduction**.
